# Урок 1: RSC vs Client, payload vs hydrate

Критерий: **1**

Docs: [Server and Client Components](https://nextjs.org/docs/app/getting-started/server-and-client-components)

Роли: Юра пишет код урока руками. Чат — подходы и маленький пример. Агент — только согласованная рутина. Полных исходников здесь нет; примеры — в чате на уроке.

## В продукте

Появляются `/` (заведение: название, адрес, часы, телефон) и `/menu` (разделы + блюда: имя, цена, состав, вес, бейдж). Список и цена — RSC. Клиентские острова: фильтр раздела и accordion состава. Отдельного URL блюда нет. Кабинета нет.

## Подходы

**A.** Каталог — Server Component; `'use client'` только на фильтре и accordion. Серверное дерево приезжает в RSC Payload; гидратируются острова.

**B.** Весь `/menu` пометить `'use client'` и отдать список как клиентское дерево. Один файл, но гидратация всего каталога и клиентский JS на каждое блюдо.

**Не SPA-привычка.** Не `useEffect` / React Query / `fetch('/api/menu')` с гидрацией всего меню. Это прячет критерий 1 и ломает [зафиксированное чтение из RSC](../decisions.md).

## Зафиксировано

[decisions.md](../decisions.md), 2026-10-12: первый срез `/` + `/menu`; клиент только островами (фильтр, accordion); карточки блюда отдельным URL нет; одно заведение; CSS Modules; SQLite; ядро App Router + React + TypeScript без Zustand / React Query / NextAuth / UI-кита. Не переоткрываем.

## Проверка

Открыть `/` и `/menu`. View Source: имена блюд уже в HTML. Network: RSC Payload отдельно от JS-чанков островов. Accordion раскрывается после hydrate; фильтр не требует, чтобы список был Client Component. Если гидратится весь каталог — урок не закрыт.

## Фразы на интервью

1. «Каталог приезжает в RSC Payload уже деревом; гидратируются только фильтр и accordion.»
2. «RSC Payload ≠ hydration: payload описывает серверные узлы, hydrate — только у Client Components.»
3. «`'use client'` — граница бандла, не граница данных: список и цена остаются на сервере.»
