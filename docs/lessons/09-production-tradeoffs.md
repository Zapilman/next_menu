## В продукте

Не новая фича QR-меню, а прод-проверка уже собранного среза и уметь назвать компромиссы. Сценарий гостя: QR → `/` → `/menu` → `/menu/[section]`. Позже тот же контур с кабинетом: логин → цена → гость видит revalidate. React Query — только контраст на том же фильтре раздела, не замена RSC.

## Подходы

**A.** Критерий 8: `next build` + `next start` локально. Смотреть таблицу маршрутов (static `/`, ISR `/menu`, static params разделов, dynamic кабинет). Объяснить, чем prod cache отличается от `next dev`. Критерий 9: на одном фильтре сравнить RSC+острова vs «вынести каталог в React Query» — словами и маленьким примером в чате, не переписывая фундамент.

**B.** «На dev работает — значит прод ок» / «давайте сразу Vercel+Docker+CI». Это раздувает ops и прячет, что Full Route Cache виден только в prod.

**Не SPA-привычка.** Не объявлять React Query новым каноном после контраста. Не тащить Kubernetes, APM, Tailwind «к деплою».

## Зафиксировано

[decisions.md](../decisions.md), 2026-10-12: главная проверка — локальные `next build` + `next start`; Vercel опционально как read-only публичное меню; запись кабинета только на локальном `next start`; analyzer в уроке 6; без Docker/CI/`standalone` в первом срезе. Не переоткрываем.

## Проверка

`next start`: гость открывает `/` и `/menu` без логина, metadata на месте. `Link` в раздел — без полной перезагрузки. Build output совпадает с уроками 2 и 5 (static / ISR / params). Кабинет в output — dynamic. Контраст Query: те же блюда, другой кэш — уметь сказать, какой слой Next.js при этом пропадает.

## Фразы на интервью

1. «Full Route Cache и размеры чанков смотрю в `next build`/`next start`, не в `next dev`.»
2. «Нет единственного правильного стека: RSC-каталог выигрывает SEO и серверный кэш; SPA+Query — если интерактив и персональные данные, не гостевое меню.»
3. «SQLite честен для Action, но ephemeral FS на Vercel ломает запись — поэтому кабинет проверяем на `next start`, а Vercel оставляем read-only.»
