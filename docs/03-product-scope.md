# Продуктовый срез

Только учебное QR-меню. Любая фича вне среза — отказ, пока её нет в уроке и в [decisions.md](./decisions.md).

## Что решить до кода

- Какие маршруты в уроке 1
- Нужна ли карточка блюда отдельной страницей
- Кабинет: нет / позже / сразу
- Что явно не делаем, даже если ChoiceQR это умеет

## Рекомендуемый дефолт

Первый срез (публичный, без логина):

| Страница | Содержание | Зачем в учёбе |
|----------|------------|---------------|
| Заведение | Название, адрес, часы, телефон | Публичный профиль, SEO, статика |
| Меню целиком | Разделы + блюда: имя, цена, состав, вес, бейдж вроде «новинка» | Каталог, RSC, кэш, streaming |
| Раздел (опционально) | Как `/section:menyu/garbuzove-menyu` | Отдельный URL, metadata, `generateStaticParams` |

Позже, отдельным уроком, если решим:

- Тонкий кабинет: вход + список блюд + смена цены/наличия. Без ролей сложнее «админ сети», без заказов.

Не в продукте (не критерии):

- Корзина, заказ к столу, оплата, доставка
- Отзывы, лояльность, чаевые, столики
- Несколько заведений, конструктор QR, админка сети
- Мультиязычность как фича, дизайн-система, анимации «как у ChoiceQR»

Данные блюда — реалистичные поля, не визуальный клон: название, описание/состав, цена, вес, метки.

## Альтернативы

- Только лендинг заведения без меню — не закрывает каталог (критерии 1–3, 7).
- Сразу кабинет — раньше auth/Actions, больше отвлечения.
- Полный ChoiceQR — продуктовый объём, мало архитектуры на строку кода.
- SPA-каталог с клиентской фильтрацией всего меню — удобно, плохо для RSC/SEO-уроков.

## Компромиссы

- Полное меню в одном RSC-дереве vs пагинация: для учёбы лучше дерево секций + Suspense, не бесконечный скролл.
- Детали блюда в списке vs `/dish/[id]`: список проще; отдельный URL лучше для metadata и not-found.
- «Наличие» как поле в JSON без кабинета: можно показать ререндер/ревалидацию позже, когда появится запись.

## Зафиксировано (см. [decisions.md](./decisions.md))

- Страницы ради техник, не визуальный клон ChoiceQR
- Первый срез: `/` (заведение) + `/menu` (полное меню)
- `/menu/[section]` — отдельный урок после каталога (`generateStaticParams`, metadata, `not-found`, Router Cache)
- Отдельного URL блюда нет: детали в списке, чтобы был смысл в Client Components
- Одно заведение, без КБЖУ/аллергенов как фичи, без корзины/заказов
- Кабинет — после публичного среза
